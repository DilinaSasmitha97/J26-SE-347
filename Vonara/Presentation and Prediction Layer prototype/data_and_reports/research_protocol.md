# Research Protocol — Component 4

**Member:** Wijethunge W M V (IT23256750) · **Project:** J26-SE-347

This document fixes the experimental method *before* results are quoted, so
that later numbers cannot be produced by adjusting the method to suit them.

---

## 1. Research questions

**RQ1 — Intent-driven strategy selection.**
Does query semantic intent, combined with statistical structure, select
forecasting models better than any single fixed model?
*Null hypothesis:* the dual-signal selector performs no better than the best
fixed model. *Status:* not yet rejected on mean RMSE (see baseline_report §2.2).

**RQ2 — Predictive grammar extension.**
Can forecast overlays, confidence bands and anomaly markers be generated
automatically from query semantics as composable extensions of a chart grammar,
without per-chart special-casing?
*Measured by:* the fraction of base charts extended without bespoke code, and
the explicit declaration of undefined cases.

**RQ3 — Unified temporal grounding.**
Can one summarization pipeline verify both historical and predictive statements,
eliminating unsupported numbers across both temporal dimensions?
*Measured by:* grounding rate; and, in LLM mode, verifier rejection rate.

**RQ4 — Adaptive anomaly thresholds.**
Do dataset-adaptive thresholds detect more true anomalies than static thresholds
without increasing false positives?
*Measured by:* precision, recall, F1, FPR against injected ground truth.
*Status:* supported — recall 0.25 → 0.50 at FPR 0.000.

## 2. Datasets

**Synthetic (primary).** Generated by `synthetic_data.py` from a known process:

```
value(t) = level + trend·t + seasonal(t) + noise(t) [+ injected anomalies]
```

Synthetic data is used deliberately, not for convenience: **anomaly precision
and recall cannot be measured without ground-truth labels**, and no public
business dataset carries them. The generator is the only source that knows
where the anomalies actually are.

Coverage: 12 benchmark scenarios spanning 4–48 periods, trend ∈ {strong up,
flat, down}, seasonality ∈ {none, mild, strong}, noise CV ∈ {0.03 … 0.55}.

**Public benchmarks (planned).** Spider and BIRD questions relabelled to the
9-intent taxonomy, to test intent classification against phrasing this project
did not author.

**Real tenant data.** Not used. Per the TAF ethics position, no organisational
data is involved at this stage.

## 3. Metrics and their justification

| Metric | Applies to | Why this metric |
|---|---|---|
| Accuracy, macro F1 | intent | Macro F1 is reported alongside accuracy because class support is unbalanced (2–11) |
| RMSE, MAE | forecast | RMSE penalises large misses; MAE is scale-honest. Both reported |
| MAPE (mean **and** median) | forecast | Mean MAPE is dominated by any single unforecastable series, so the median is reported beside it — never instead of it |
| Precision, recall, F1, FPR | anomaly | FPR is essential: a detector that flags everything scores high recall and is useless |
| Grounding rate | summary | Fraction of numeric assertions traceable to a computed claim |

---

## 4. Controls and baselines

Every claim is measured against a control that could beat it:

| Claim | Control |
|---|---|
| Dual-signal model selection | each of the 3 fixed models applied to every scenario |
| Adaptive anomaly thresholds | textbook static 1.5·IQR / z=3, no detrending |
| Hybrid query understanding | rule-only mode (also the default) |
| Grounded summarization | LLM narration without the verifier |

## 5. Validity safeguards

**Out-of-sample only.** Forecast accuracy is reported from a held-out backtest
(`prediction.backtest`), never from in-sample residuals. In-sample MAPE is
computed but used only as a fit diagnostic inside the response.

**Fixed seeds.** Every generator takes an explicit seed. Re-running
`evaluate.py` reproduces every figure exactly.

**Deterministic default.** All reported numbers are produced with
`LLM_PROVIDER` unset, so results do not depend on a model version or an API key.

**Dev/test split.** `intent_testset.json` marks 10 dev cases (used for lexicon
tuning) and 38 test cases (reported). Only the test split is quoted.

**Negative results are reported.** Where the method loses to a baseline, the
loss is stated with its cause rather than omitted or tuned away. Two such
results are recorded in `baseline_report.md` §2.2 and §3.

## 6. Known threats to validity

| Threat | Severity | Handling |
|---|---|---|
| Intent test set authored by the lexicon's author | **High** | Disclosed at every mention of the 100 % figure; independent split planned |
| Benchmark scenarios designed alongside the selection rules | **Medium** | Disclosed; 100 % selection agreement is qualified accordingly |
| Synthetic data may not match real business volatility | Medium | Noise/volatility swept across a wide range; real-data check planned in Phase 3 |
| Single 3-period holdout is a small test | Medium | Rolling-origin backtesting planned in Phase 2 |
| Confidence intervals not yet calibration-tested | Medium | Coverage check planned: does the 95 % band contain 95 % of held-out actuals? |
| 172 observations / 12 anomalies is a small anomaly sample | Medium | Wider labelled sweep planned |

## 7. Reproduction

```bash
pip install -r requirements.txt
python evaluate.py --json=evaluation_results.json     # all four suites
python evaluate.py intent                             # one suite
python evaluate.py --llm                              # adds hybrid-mode intent run
```

Expected runtime: under 30 seconds in deterministic mode.
